## ขั้นที่ 1 — ปิดช่องอนุมัติกลุ่ม

**ปัญหา** `bulkApproveApprovals()` ([index.html:7694](../index.html)) ไม่ตรวจสิทธิ์คงเหลือและไม่ลง audit ขณะที่ `approveRequest()` ทำทั้งสองอย่าง ([index.html:7936](../index.html)) ทางที่เร็วกว่าจึงเป็นทางที่ไม่มีการ์ด

**ลำดับงาน**

1. **เขียนเทสต์ก่อนแก้** `tests/bulk_approve.test.js` คุม 4 ข้อ
   - เลือก 3 ใบ โดยใบหนึ่งเกินสิทธิ์ → ต้องคืนรายการที่เกินสิทธิ์ออกมา ไม่ใช่อนุมัติเงียบ ๆ
   - อนุมัติผ่านทางกลุ่ม → ต้องมี `auditLog('leave-approve-over-quota', ...)` ต่อใบที่เกิน เท่ากับทางทีละใบ
   - ใบที่ไม่เกินสิทธิ์ในชุดเดียวกัน → ต้องผ่านตามปกติ ไม่ถูกบล็อกไปด้วย
   - สถานะที่ไม่ใช่ `pending` ที่หลุดเข้ามาในชุด → ต้องถูกข้าม (พฤติกรรมเดิม ห้ามเปลี่ยน)
2. **แยกตรรกะตรวจสิทธิ์ออกเป็นฟังก์ชันร่วม** เช่น `quotaCheckForApproval(req)` คืน `{over: bool, remaining, excess, name}` แล้วให้ทั้งทางทีละใบและทางกลุ่มเรียกตัวเดียวกัน — ห้าม copy เงื่อนไขไปวางซ้ำ เพราะต้นเหตุของบั๊กนี้คือมีตรรกะสองชุด
3. **เปลี่ยน `confirm()` เป็นใบสรุป** แสดงจำนวนแยกตามประเภท และ **แยกรายการที่เกินสิทธิ์ออกมาให้ติ๊กออกได้ตรงนั้น** ไม่ใช่แค่เตือนแล้วให้กดผ่าน
4. **แก้แถบเครื่องมือที่หายตอนเลื่อน** `#apvBulkBar` ([index.html:7788](../index.html)) ใช้ `position:sticky;top:0` ซึ่งไร้ผลเพราะตัวครอบมี `overflow-x:hidden` → เปลี่ยนเป็น `position:fixed` ที่ขอบล่างจอบนมือถือ (อยู่ในระยะนิ้วโป้งด้วย) และเพิ่ม `position:sticky` ให้ `<thead> th`

**ตรวจว่าผ่าน** รัน `node tests/bulk_approve.test.js` และชุดทั้งหมดต้องผ่าน · เลือก 20 ใบในสำเนาทดสอบแล้วต้องเห็นใบสรุปที่ชี้รายการเกินสิทธิ์ · เลื่อนลงสุดแล้วแถบยังอยู่

**ถ้าพัง** ย้อน commit เดียว ไม่มีการเปลี่ยนโครงสร้างข้อมูล

## ขั้นที่ 2 — หน้าอนุมัติบนมือถือ

**ปัญหา** ที่ ≤768px คอลัมน์ปุ่มถูกตรึงขวาด้วยพื้นหลังโปร่ง 70% ([index.html:784-791](../index.html)) กินพื้นที่ 53% ของจอ 375px และทับชื่อพนักงานราว 80px ปุ่มสูง 31px ตารางกว้างจริง 937px

**ลำดับงาน**

1. **เลิกใช้ตารางที่ ≤768px** ใน `drawApprovalList()` เพิ่มทางเลือกการเรนเดอร์แบบการ์ด เช็คด้วย `window.matchMedia('(max-width:768px)').matches`
2. **โครงการ์ดต่อคำขอ** — ชื่อพนักงาน + ประเภทการลาเป็นหัวข้อ (ชื่อต้องอ่านได้เต็ม ไม่ถูกอะไรทับ) · วันที่และจำนวนวันเป็นบรรทัดรอง · เหตุผลและไฟล์แนบเป็นชิปเล็ก · แล้วปุ่ม **อนุมัติ/ปฏิเสธ เต็มความกว้าง สูง 48px** วางล่างสุด
3. **ทำเครื่องหมายใบที่ต้องคิดก่อนกด** ใบที่เกินสิทธิ์และใบลาป่วยที่ไม่มีใบรับรองแพทย์ต้องมีสัญลักษณ์ที่เห็นได้โดยไม่ต้องอ่านข้อความ — ตอนนี้ทุกแถวหน้าตาเหมือนกันหมด
4. **ถ้ายังต้องคงตารางไว้** (เช่น ยังไม่มีเวลาทำการ์ด) อย่างน้อยเปลี่ยนพื้นหลังคอลัมน์ตรึงจาก `var(--glass-bg)` เป็น `#fff` ทึบ และย้ายชื่อพนักงานไปอยู่ในคอลัมน์ที่ถูกตรึงแทนปุ่ม

**ตรวจว่าผ่าน** ที่ 375px ชื่อพนักงานทุกแถวอ่านได้ครบโดยไม่มีอะไรทับ · ปุ่มสูง ≥44px · ไม่มีการเลื่อนแนวนอนในการ์ด

## ขั้นที่ 3 — ผลลัพธ์การรีเซ็ตรหัสผ่าน

**ปัญหา** `resetPassword()` ([index.html:8369](../index.html)) แสดงรหัสใหม่ใน `toast()` ซึ่งอยู่ได้ 3 วินาที ([index.html:4127-4134](../index.html)) ไม่มีปุ่มคัดลอก และ toast ตัวถัดมาขึ้นทับที่พิกัดเดียวกันเป๊ะ เพราะทุก toast ใช้ `top:20px;right:20px` ตายตัว

**ลำดับงาน**

1. **แก้ที่ต้นเหตุของการทับกันก่อน** ทำให้ `toast()` วางซ้อนเป็นชั้น (นับจำนวน toast ที่ยังอยู่แล้วเลื่อน `top` ลงมาตามลำดับ) — เป็นการแก้ที่ได้ผลกับทุกจุดในแอป ไม่ใช่แค่หน้ารีเซ็ต
2. **เปลี่ยนผลลัพธ์การรีเซ็ตเป็น modal ที่ค้างอยู่** ชื่อและรหัสพนักงานด้านบน · รหัสผ่านในช่อง monospace พร้อมปุ่มคัดลอก · ผลการสร้างบัญชี Auth อยู่ในแผงเดียวกัน จะได้ไม่มีข้อความสองอันขัดกันเอง · ปิดได้ด้วยปุ่มเดียวที่ชัดเจน
3. **ใส่คำยืนยันที่มีชื่อคนก่อนรีเซ็ต** ตอนนี้กดปุ่มแล้วเด้ง `prompt()` ทันที บนมือถือที่ชื่อถูกปุ่มทับ (ขั้นที่ 2) แอดมินมองไม่เห็นด้วยซ้ำว่ากำลังรีเซ็ตของใคร
4. **เพิ่ม Escape และล็อกการเลื่อนพื้นหลังให้ modal ทุกตัว** `showModal()` ([index.html:4105](../index.html)) ตอนนี้ไม่มีทั้งสองอย่าง — แก้ครั้งเดียวได้ผลทั้งแอป
5. **ลบคำแนะนำที่ทำบนมือถือไม่ได้** ข้อความที่บอกให้ "เปิด Console (F12)" ต้องเปลี่ยนเป็นแสดงค่าที่ต้องใช้บนหน้าจอโดยตรง

**ตรวจว่าผ่าน** ต่อยอด `tests/auth.test.js` · รีเซ็ตจริงหนึ่งครั้งแล้วรหัสยังอยู่บนจอจนกว่าจะกดปิด · ยิง toast สองตัวติดกันแล้วต้องไม่ทับกัน

## ขั้นที่ 4 — ระบบตัวอักษรไทยและคอนทราสต์

**ปัญหา** ทั้งเครื่องตรวจอัตโนมัติและคนรีวิวชี้จุดเดียวกัน: `--muted: rgba(15,37,87,0.55)` ([index.html:43](../index.html)) = 3.6:1 ต่ำกว่าเกณฑ์ 4.5:1 และใช้กับป้ายฟอร์มทั้งระบบ · `body` ตั้ง `letter-spacing:-0.01em` ([index.html:59](../index.html)) ติดลบกับภาษาที่มีวรรณยุกต์ซ้อน · `.login-card .subtitle` ใช้ `letter-spacing:0.2em` ([index.html:124](../index.html)) และ `.nav-section` ใช้ `0.12em` + uppercase ([index.html:423-428](../index.html)) ซึ่งทำลายขอบเขตคำของภาษาไทยที่ไม่มีช่องว่างระหว่างคำ

**ลำดับงาน**

1. เพิ่มกฎเดียวครอบทั้งระบบ
   ```css
   :lang(th), [lang="th"] { letter-spacing: normal; text-transform: none; }
   ```
   วางไว้ท้ายสุดของ `<style>` เพื่อให้ชนะกฎเดิมโดยไม่ต้องไล่แก้ทีละจุด (หน้าเว็บตั้ง `lang="th"` ไว้แล้วที่ `<html>`)
2. เพิ่มความเข้ม `--muted` เป็นราว `rgba(15,37,87,0.78)` แล้ววัดซ้ำให้ได้ ≥4.5:1 บนพื้นขาวและบนการ์ดกระจก
3. ตั้งพื้นขนาดข้อความรองที่ 13px — ตอนนี้มีข้อความ 10-11px อยู่ 41 จุดในโค้ด และหน้าตั้งค่ามีต่ำกว่า 12px ถึง 47 จุด
4. จัดลำดับฟอนต์ให้ Sarabun มาก่อนสำหรับช่วงอักขระไทย หรือโหลดด้วย `unicode-range` — ตอนนี้เครื่อง Apple เรนเดอร์ฟอนต์ไทยของระบบ ส่วน Android เรนเดอร์ Sarabun กลายเป็นคนละแบบอักษรในฝูงเครื่องเดียวกัน ทั้งที่ดาวน์โหลด Sarabun มาแล้ว 6 น้ำหนัก
5. ลดจำนวนน้ำหนักฟอนต์ที่โหลด จาก 15 น้ำหนักเหลือเท่าที่ใช้จริง (ปกติ 3-4 พอ)

**ตรวจว่าผ่าน** รันตัววัดคอนทราสต์ในเบราว์เซอร์ซ้ำ ต้องไม่เหลือข้อความที่ต่ำกว่าเกณฑ์ · หน้าล็อกอินต้องไม่เห็นตัวอักษรไทยถูกยืดอีก

## ขั้นที่ 5 — กริดแดชบอร์ดบนมือถือ

**ปัญหา** กฎย่อหน้าจอจับคู่จากข้อความ inline style ตรงตัว ([index.html:821-822](../index.html)) แต่แดชบอร์ดเขียน `2fr 1fr` และ `repeat(3,1fr)` จึงไม่เข้าเงื่อนไข วัดที่ 375px การ์ดสิทธิ์วันลาเหลือกว้าง 90px ไทล์คำขอเหลือ 67px

**ลำดับงาน**

1. ให้กริดทั้งสองมีคลาสจริง เช่น `.dash-split` และ `.request-tiles` แทน inline style
2. ตั้งกฎในบล็อก `@media (max-width:768px)` ให้ `.dash-split` เหลือคอลัมน์เดียว และ `.request-tiles` ใช้ `repeat(auto-fit, minmax(150px, 1fr))`
3. **ลบตัวเลือกที่จับจากข้อความทิ้ง** แล้ว `grep` หา `grid-template-columns` ที่เป็น inline style ทั้งไฟล์ แก้ให้เป็นคลาสทั้งหมด — ตราบใดที่ยังใช้วิธีจับจากข้อความ บั๊กประเภทนี้จะกลับมาทุกครั้งที่มีคนเขียนกริดใหม่
4. ขณะไล่แก้ ให้ตรวจ `.modal-content` ในบล็อกมือถือด้วย ([index.html:801](../index.html)) — `showModal()` ไม่เคยสร้าง element ชื่อนี้ กฎ "modal เต็มจอบนแนวตั้ง" จึงไม่เคยทำงานเลย

**ตรวจว่าผ่าน** ที่ 375px ทุกการ์ดบนแดชบอร์ดกว้างอย่างน้อย 150px และตัวเลขไม่ล้นขอบการ์ด

## ขั้นที่ 6 — เก็บกวาดรอบสุดท้าย

- ลบ `<div class="icon"></div>` ที่ว่างเปล่า 15 จุด (ร่องรอยการลบอิโมจิ) แล้วใส่ไอคอน SVG หรือตัดทิ้งพร้อมระยะห่าง
- ลบช่องว่างลอยหน้าหัวข้อ `<h1>` 18 จุด
- แท็บที่มี `(0)` ให้จางลง ไม่ควรเด่นเท่าแท็บที่มี 20 รายการ
- แบนเนอร์ changelog `v1.4.51 Update` ในหน้ารายงาน — ตัดออก ผู้ใช้ไม่ใช่ผู้พัฒนา
- เลื่อนการโหลดไลบรารีหนักไปหลังล็อกอิน: xlsx (425KB) และ html2canvas (199KB) ไม่ถูกใช้บนหน้าล็อกอินเลย แต่ถูกโหลดทุกครั้ง
- ช่องกรอกในหน้าล็อกอินตั้งเป็น 16px (ตอนนี้ 14px ทำให้ iOS ซูมเองทุกครั้งที่แตะ) และเพิ่ม `autocomplete="username"` กับ `autocomplete="current-password"`
- ผูก `<label for>` กับช่องกรอก — ตอนนี้ 0 จาก 51 ช่อง ทำให้แตะที่ป้ายแล้วไม่โฟกัสช่อง และโปรแกรมอ่านหน้าจออ่านไม่ครบ

## สิ่งที่อยู่นอกแผนนี้โดยตั้งใจ

**การเข้าถึงด้วยแป้นพิมพ์ทั้งระบบ** เมนู 18 รายการเป็น `<div onclick>` ทั้งหมด ทั้งไฟล์มี `aria-` อยู่ 1 จุดและ `tabindex` 0 จุด การแก้ให้ครบคือการรื้อชั้นนำทางใหม่ ซึ่งใหญ่เกินกว่าจะพ่วงมากับรอบนี้ ควรเป็นงานแยกที่ตัดสินใจกันก่อนว่าจำเป็นแค่ไหนกับฐานผู้ใช้จริง

**การรื้อภาษาภาพทั้งหมด** ตกลงกันแล้วว่าคงโครงกระจกน้ำเงินไว้ รอบนี้แก้เฉพาะระบบตัวอักษรให้เข้ากับภาษาไทย

**หน้าตั้งค่า 53 ช่องและเมนู 18 รายการ** เป็นปัญหาเชิงโครงสร้างข้อมูล ไม่ใช่เชิงภาพ ควรวัดการใช้งานจริงจาก `auditLog` ก่อนตัดสินใจตัดหรือยุบ
